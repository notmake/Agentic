# Agent 心智模型：六要素与实验方法

> 这份笔记回答一个问题：做 agent 项目，怎样从"会写 loop"变成"能判断为什么行/不行"。

## 1. 六要素模型

```
Agent = 模型 × 上下文策略 × 动作空间 × 环境/验证器 × 循环控制 × 预算
```

每个要素都是可独立调节的旋钮；成熟的做法是**一次只动一个**，并预测哪个失败类会迁移。

| 要素 | 关键问题 | 本项目中的证据 |
|---|---|---|
| 模型 | 能力上限、指令遵循、工具调用稳定性 | 27B Q4 在 10 实例 6 resolved；同实例自研/框架结果不同，说明模型不是唯一变量 |
| 上下文策略 | 窗口多大、怎么压缩、丢了什么 | 16K 下自研 agent 压缩 5 次、丢 36 步 → LIMIT_ERROR 空补丁 |
| 动作空间 | 有哪些工具、协议是原生还是文本 | 原生 tool_calls 遇非法 JSON 直接 500；prompt-mocked 协议消除空补丁 |
| 环境/验证器 | 沙箱、测试、判定标准 | gold 3/3 先证明评测可信；agent 与评测共用镜像 |
| 循环控制 | 步数、重试、失败回退、终止条件 | 40 步触顶、格式错误上限、代理重试 3 次无效 |
| 预算 | token、时间、显存、成本 | 16K/单槽/q8 KV 是稳定性与能力的折中；单实例 5–60 分钟 |

## 2. 失败分类是认知的核心

解决率只是一个数；**失败分布才告诉你下一个旋钮该往哪转**。

| 分类 | 含义 | 该动哪个要素 |
|---|---|---|
| FORMAT_ERROR | 输出/协议不合法 | 动作空间、解析层 |
| LIMIT_ERROR | 步数/时间/上下文触顶 | 上下文策略、循环控制、预算 |
| LOCATE_ERROR | 没定位到问题 | 动作空间（search）、提示 |
| PATCH_ERROR 5d/5e | 改错/部分修复/回归 | 模型能力、验证闭环 |
| PATCH_ERROR 5b | 没跑测试就提交 | 循环控制（提交前校验） |
| TEST_ENV_ERROR | 镜像/评分故障 | 环境/验证器，不是模型 |

## 3. 证据链写作模板

每个失败都按这个格式记录（`LEARNINGS.md`）：

```
现象：实例 X 空补丁
证据：日志出现 "Failed to parse tool call arguments"（步骤 N）
定位：错误在 llama-server 原生 parser，不在 OpenHands
假设：绕过原生解析即可
验证：native_tool_calling=False，同实例重跑 → 有补丁
结论：协议层问题；失败类从 FORMAT_ERROR 迁移到 PATCH_ERROR
```

## 4. 单变量实验矩阵（下一步）

| 实验 | 固定 | 变量 | 观察指标 |
|---|---|---|---|
| A 协议 | 20 实例、27B、16K | native vs prompt-mocked | FORMAT_ERROR 数、耗时 |
| B 模型 | 同 20 实例、同协议 | 27B Q4 vs 14B AWQ vs 30B-Coder | 解决率、5d/5e 分布 |
| C 上下文 | 同实例、同模型 | 8K vs 16K | LIMIT_ERROR、压缩次数 |
| D 工具面 | 同实例 | bash+view+write vs 加 search | LOCATE/5b 是否下降 |
| E 框架 | 同实例 | 自研 vs OpenHands | 解决率、轨迹长度 |

## 5. 读源码的正确姿势

不要通读框架。只读你依赖的**接缝**：

- OpenHands：`sdk/llm/mixins/non_native_fc.py`（工具协议）、`sdk/llm/llm.py`（配置/重试）
- llama.cpp：chat parser（错误从哪来）、server 参数（ctx/KV/并行）
- swebench：`harness/run_evaluation.py`（镜像、超时、报告格式）

读到一个能解释你观测现象的代码路径就停，写进 ADR。
